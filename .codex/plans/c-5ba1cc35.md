## Risks

- Structured snapshots remove PNG history overhead but long paths and embedded PNGs can still consume substantial memory. Enforce the specified file, image, object, point, and text limits before decoding and keep the existing 50-entry history cap.
- Display pixels, logical document coordinates, and `devicePixelRatio` are currently conflated. Every renderer, pointer, text-editor, hit-test, selection, and export path must use the same explicit transform to avoid drift after resize or on high-DPI displays.
- Text metrics can differ between operating systems. Restrict version 1 to the existing system-sans font token and share the same Canvas text measurement implementation between rendering, hit testing, selection bounds, editing layout, and export.
- Scaling path geometry can produce unstable results for zero-width or zero-height bounds. Treat each axis independently, disable the corresponding scale component when its extent is zero, and reject non-finite geometry at the document boundary.
- Base64 increases embedded PNG size and duplicates bytes during JSON parsing and Tauri IPC. Validate file metadata before reading, validate decoded size before image allocation, cache one decoded background image, and release replaced image references promptly.
- Native full-path I/O expands the Rust command boundary beyond the current basename-only app-data storage. Accept paths only after native user selection, repeat extension and file-kind validation in Rust, use least-privilege dialog permissions, and never infer arbitrary paths from document content.
- A valid project can still contain an image that Rust accepts but the webview cannot decode. Keep project opening transactional until frontend background decoding succeeds, and preserve the prior document and history on every load failure.
- Flattened legacy PNG files cannot regain editable objects. Importing them as a single embedded locked background preserves appearance and allows new editable foreground work, but the README and UI must not imply vector recovery.
